# AN-02 Business Rules (MVP)

Дата фиксации: 2026-03-03

## Роли

- `client`: пользователь Telegram-бота, создает/просматривает/отменяет свои записи.
- `manager`: получает уведомления о новых и отмененных записях, контролирует процесс.
- `admin`: управляет услугами и статусами через Admin API.

## Статусы записи (`booking_status`)

- `new`: новая запись, создана клиентом.
- `confirmed`: подтверждена менеджером/админом.
- `done`: услуга оказана.
- `cancelled`: запись отменена.
- `no_show`: клиент не пришел.

### Разрешенные переходы статусов

- `new -> confirmed`
- `new -> cancelled`
- `confirmed -> done`
- `confirmed -> cancelled`
- `confirmed -> no_show`

Терминальные статусы: `done`, `cancelled`, `no_show`.

## Правила отмены

- Клиент может отменить запись в статусах `new` и `confirmed`.
- Повторная отмена запрещена (идемпотентно возвращаем текущее состояние как `cancelled`).
- После `done` и `no_show` отмена недоступна.
- Администратор может отменить запись в статусах `new`/`confirmed` только с обязательной причиной.
- При админской отмене клиент получает уведомление с причиной отмены.

## Правила no-show

- `no_show` выставляет только `manager` или `admin`.
- `no_show` применим только к записи в `confirmed` после фактического времени визита.
- После `no_show` запись считается завершенной и не может быть изменена клиентом.

## Уведомления

- При создании записи: уведомление менеджеру (`manager_alert`) + планирование `reminder_24h` и `reminder_2h`.
- При отмене: уведомление менеджеру о статусе `cancelled`.

## Критерий готовности AN-02

- Роли, статусы и правила отмены/no-show зафиксированы.
- Правила согласованы с текущими enum в БД и логикой worker/bot.
