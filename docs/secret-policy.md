# INF-03 Secret Policy

Дата фиксации: 2026-03-03

## Где храним секреты

- `local`: в `.env` (файл не коммитится).
- `staging`: только в secret manager/CI variables.
- `prod` (вне MVP): только в secret manager.

## Что считается секретом

- `TELEGRAM_BOT_TOKEN`
- `TELEGRAM_MANAGER_CHAT_IDS` (внутренний контур)
- `POSTGRES_PASSWORD`
- приватные DSN/URL для staging/prod

## Обязательные правила

- Не коммитить реальные секреты в Git.
- В репозитории хранить только шаблоны (`.env*.example`).
- Логи не должны содержать значения токенов/паролей.
- Ротация при любом подозрении на утечку.

## Ротация и инциденты

1. Отозвать старый Telegram token через BotFather.
2. Выпустить новый token.
3. Обновить секреты в staging.
4. Перезапустить `bot` и `worker`.
5. Проверить `/health` и тестовое сообщение в канал/чат менеджера.

## Минимальный чеклист перед релизом

- В `.env` локально нет продовых значений.
- В `README` нет реальных токенов/паролей.
- CI использует переменные окружения, а не хардкод.
