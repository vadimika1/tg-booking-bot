# DOC-01 Demo Scenario (10-12 минут)

Дата: 2026-03-03

## Цель демо

Показать полный MVP-путь: клиентская запись в Telegram, конфликт слота, отмена, уведомления и базовая админка API.

## Подготовка

1. Запустить сервисы: `docker compose up --build -d`
2. Применить миграции: `docker compose run --rm api alembic upgrade head`
3. Заполнить 1-2 услуги через API (`POST /api/services`)
4. Убедиться, что бот добавлен в канал менеджера и имеет права публикации.

## Сценарий показа

1. Клиент открывает бота, нажимает `Записаться`.
2. Выбирает услугу, дату и доступный слот.
3. Вводит имя и телефон, подтверждает запись.
4. Менеджер получает уведомление в канал.
5. Показать `Мои записи` в боте.
6. Отменить запись из бота.
7. Показать в канале уведомление об отмене.
8. Через API показать, что статус записи стал `cancelled`.

## Smoke-check во время демо

- `GET /health` возвращает `ok`.
- `GET /api/slots` возвращает свободные интервалы.
- Повторное бронирование того же слота дает `409`.
- `PATCH /api/bookings/{id}/status` меняет статус.

## Риски и обход

- Если список услуг пуст: быстро создать услуги через `POST /api/services`.
- Если нет уведомлений в канал: проверить `TELEGRAM_MANAGER_CHAT_IDS` и права бота в канале.
- Если БД недоступна: перезапустить `postgres` и `api` через `docker compose up -d`.
